## 本仓是什么

思维导图桌面工具（对标亿图脑图 MindMaster）：大纲 ⇄ 树同构编辑、多页画布、
.xmind 导入导出、原生菜单栏、权益/配额门控骨架、AI 单点生成入口。

- 技术栈：Tauri 2 + React 19 + AntD 6 + Zustand 5 + Vite；Rust 侧 12 个 .rs 共 3281 行
- 前端规模（实测）：`src` 下 ts/tsx 共 62 个，其中 engine 17、views 14、services 7、stores 4
- 测试（实测）：`tests/` 21 个测试文件 + 自研零依赖 runner（`node tests/run.mjs`，esbuild 逐文件打包，与 terminal 同款）
- 最大单件：`src/engine/layout.ts` 1414 行（版式引擎）
- 文档资产：`doc/复刻方案/00_业务逻辑梳理.md` 448 行（§3.1–3.19 蓝本拆解）

## 核心结论

1. **质量底盘是同族里好的一档**：980 例前端测试 + 41 例 Rust 测试 + typecheck/build/cargo check 全绿、生产 unwrap 0 处。
   但这层绿有一**平台盲区**：2 例快捷键标签测试在 macOS 本机必挂（CI 的 ubuntu 跑不出来、macos job 又不跑前端测试），
   细节与修复见 [01 A-01](./01_现状审计与问题清单.md)。
2. **从未发布**：release.sh / install.sh / desktop-build.yml（tag 触发）全齐，但一次都没走过（无 v* tag）。
   首发本身就是 P0 事项，且是本方案里唯一对外不可逆动作（须用户点头）。
3. **AI 是单点入口，蓝本 §3.13 功能域未展开**：实测已通链路 =
   App「AI 生成」按钮 → `runAiInsert` → `services/ai.ts`（288 行，OpenAI-compatible）→ 复用 outline 引擎；
   密钥管理与配额展示在 OptionsView。而蓝本的四大类 AI 能力（文本/图像/产出/对话）与 Ctrl+Q AI 面板均未做——
   做不做、先做哪个是产品决策，先审计后立项（[01 A-07](./01_现状审计与问题清单.md)）。
4. **门面与治理欠账**：全组织唯一没有 README 的仓；.npmrc 把 registry 钉死在 npmmirror 会拖累 CI；
   448 行蓝本与代码之间没有映射表，新执行者难以判断"哪些已落地"。
5. **第 1 条那句"质量底盘好"要加一个限定：绿的是模型层，不是线格式层**（2026-10-10 补）。
   emmx 往返测试的判据是 `modelEquals`（比两边解析出来的对象），而 `buildShape` 根本不建模
   `ToSuper` / `<Geometries>` 路径缓存 / 第二个 `<Paragraph>` / `ShapeFormat@QuickMask` / `CX@B·P` ——
   **凡是模型里没有的东西，这类测试天生看不见**。装机差分实测（01 A-12）：只点一次「展开全部」再存盘，
   22 颗主题上上述五类码全部消失，同时多出四个我们发明的默认值，而全库 2177 例照绿。
   写路径的验收口径因此要换成"标签/属性点名器"（03 §1.3-21 末条），这一条是本方案里唯一能抓住静默损坏的量具。
   **后续（2026-10-10 批 3G）**：口径已经换成这台点名器并落进 `tests/writediff.test.ts`（键级 + 值级两层），
   A-12 与顺带抓到的 A-15 都办掉了；同时承认这台点名器的盲区 —— 它只数键不数值，
   所以"值级削码"（`TextFormatMask` 被我们的常数洗掉、`Character@BkColor` 丢）必须靠合成夹具按值钉。
   **再后续（2026-10-10 批 3J）**：这台键级点名器的盲区真的咬到了 —— A-17 改的全是值（`Size/Family/Color/Width/Height`），
   键计数一格都不动，"全绿 + 键级差分干净"两条一起通过却看不见改动内容。于是装机侧补了**值级差分器**
   （`C:/zmind-tgt/a17j-disk.mjs`：把每个 Shape 块摊平成 `tag#序@属性 → 值` 再比），它当场抓到
   `CX/CY: 47.3/16.8 → 0/0` ⇒ 新立 [01 A-18](./01_现状审计与问题清单.md)。**写路径的量具现在是三层**：
   仓库内键级 + 值级（合成夹具与真样张都跑）、装机保存前后的整档值级差分、以及"重开一次看屏上"的终点核对。
   **再后续（2026-10-10 批 3K）**：这台值级差分器第一次被要求回答"数值对不对"而不只是"键在不在" —— A-18 的验收口径是
   `锚移动量 == (新文字宽 − 原文字宽)/2` 且 `内缩差 == 0`（装机实测 102/110 两颗都精确到 Δ35 / 内缩 17.30 不变）。
   同一台差分器顺带扫出两类从前没看过的量：**全档零锚计数**（改后 0/85）与**文字盒 > 形状盒 的溢出颗数**
   （未编辑 0 颗 → 编辑一轮 5 颗 ⇒ 新立 A-21）。差分器末行那两个计数器从此是本族批次的固定验收。
