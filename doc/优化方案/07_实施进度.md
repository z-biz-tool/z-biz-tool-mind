### 两个数字的坑（本轮实测出来的，据实记下）

1. **「2,678 例」不是任何克隆都能复现的数字。**
   本仓有一批断言依赖 `_research/`（亿图装机的解包样本与逐屏截图）——
   该目录在 `.gitignore` 里，**按设计不入库**（不是我们能再分发的东西）。
   持有素材的那台机器上这批断言会跑，本机与**任何新克隆、任何 CI** 都整段跳过。
   3Q-2 与 3R 记的 2,652 / 2,678 是在有素材的机器上量的。
   ⇒ **引用测试数必须写清是哪一档**：本机（无素材）是 30 文件 / 2,432 例 / **跳过 16 处分支**。
2. **跳过曾经是完全不可见的**（本轮修掉）。
   `skip()` 原来只打印一行说明、**不计数**；`run.mjs` 在没有失败时把那几行当噪声丢掉。
   于是「跑满了」与「少跑了 16 处分支」在日志上**长得一模一样**，CI 全绿。
   本轮把跳过**计入汇总行**（`PASS n / FAIL m / SKIP k`）、按文件列出、并在末尾打一段
   显眼的清单；另加 `--require-all`：有素材的机器上用它确认那批真样本断言真的跑了
   （默认不失败——素材按设计不可再分发，跳过不是失败）。
   ⇒ 16 处跳过分布在 **8 个测试文件**：emmx / fold / overlay / projections / style / theme / themelib / writediff。
   这 8 个文件**都有 A 层合成夹具**（任何环境都跑），跳过的只是「真亿图样张对照」那一组。

### 2026-10-25 契约门 + 快照口径轮：一条真 bug（列表与删除各写各的判据）+ 一道比 note/box 更强的 IPC 契约门
- **起因是家族扫描**：z-biz-tool-lead 的家族探针报「mind 有 2 个事件发了没人收」
  （Rust emit `autosave-fired` / `emmx-saved`，前端只 listen `open-path`）。
  **探针报错了** —— mind 的前端**确实在听**这两个事件：
  `src/stores/recentStore.ts` 把事件名放进常量表 `pairs`，再由 `for (const [name, handler] of pairs)`
  解构出来喂给 `listen(name, …)`；探针只认 `listen("字面量")` ⇒ **漏扫**。
  **探针自己错了要改探针**（探针的修在 z-biz-tool-lead 仓），而且
  **mind 自己因此需要一道能识别转接的门** —— note/box 那一版直接搬过来会**误报**。
- **顺带量出真 bug**（与探针无关，是自己读代码读出来的）：
  `autosave_list`（列表侧）**不挑扩展名**、`autosave_drop`（删除侧）**只准 `.emmx`** ——
  两端各写各的判据 ⇒ 文档目录里任何非 `.emmx` 的文件都会被当成快照列出来，
  而它**删不掉**（前端只会弹「这次快照没能从磁盘上带走…下次启动可能还会问一次」，
  而它永远还在 ⇒ 每次开机重复问一遍）。修法：判据抽成**一个**函数 `is_snapshot_file`，两侧共用
  ⇒ **列表 = 可删 = 计数**。详见 [01 A-26](./01_现状审计与问题清单.md)。
- **落点**：
  `src-tauri/src/backup.rs` —— `is_snapshot_file` + `autosave_list` 改用它 + `autosave_drop` 改用它
