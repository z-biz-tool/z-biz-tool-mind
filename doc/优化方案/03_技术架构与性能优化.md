4. **新发现（已修）：垂直时间线把一级分支摞回同一行**。`layoutSpine` 无论横竖主轴，

   连线随之按层分向：一级分支竖着接、再往外的子分支横着接。
5. **新发现（已修）：组织结构图（上下双向）把分支压进中心主题**。`assignSubtreeY`
   在 depth=0 时只让开自身半高，等于从根的圆心起算。实测：中心主题 × 分支A 重叠 25x18、

6. **新发现（已修）：直角折线族里混着斜线段**。这条只能靠**装机目检**发现——坐标断言全过，
   因为盒子位置本来就对，错的是画线。真机截图上 树状图（向下对称）/组织结构图（上下双向）
   的分支线中间是一段斜线，与 `buildConnectors` 上方「树/组织结构图用直角折线」的注释不符；
   上行枝的连线还从中心主题**底边**出发，先穿回父框再折上去。

   竖直分支写死「底出顶进」。处置：两个分支都改成纯轴对齐折线，进出边跟随子节点方向

7. **新发现（已修）：主轴版式（时间轴/鱼骨）四处几何真错**。来源是 §1.3-6 修完之后**重装再目检一遍**——
   上一批只对了折线的画法，没验主轴的推进量，目检第二轮才露出来。
   - ① `layoutSpine` 的推进坐标从**根圆心**（`cursor = 0`）起算，首枝的近侧缘因此落在根框之内
     （装机实测：垂直时间线 根底边 17.5、首枝顶边 15）。直角折线于是"从底边出来又折回根框里"。
     改为从根的外缘（`root.w/2` / `root.h/2`）起算。
   - ② `layoutHorizontalTreeSubtree` 里写的是 `setX(c, c)`，而 `setX` 第一行就是
     `n.x = parent.x + side * hGap(parent, n)` —— 自己当自己的父节点，每个子节点被平白多推一格
     （自身宽 + 间距），整棵子树压到下一个主分支身上。改为 `setX(c, node)`，并去掉已经走不到的
     `parent === null` 分支。
   - ③ 水平主轴把 `side`（上下交替的符号）当成子树的左右符号用，子枝甩回根框那一侧
     （实测 水平时间线 的 A一/A二 落在 x=-30，压住根框 31x16；鱼骨图（右）同一条）。
     改为：竖直主轴用 `k.side`（外侧=左右，正好同号），水平主轴沿主轴向前用 `opts.dir`。
   - ④ 沿主轴的步长用了 `estimateWidth`，那是"兄弟并排"的量法，用在横着长出去的子树上短一截
     （实测 水平时间线 的 A一一 右缘 296.5 撞进 分支C 左缘 293，压框 4x30）。
     新增 `forwardReach`：自身中心 → 子树最外缘，步长改为 `k.w/2 + forwardReach(k) + spacing`。
   - ⑤ 顺带清掉一条我自己上一批加的补丁：`buildConnectors` 里
     `code.startsWith("timeline") && code !== "timelineHorizontal"` 把 S 型时间线整族强推成直角折线，
     而它主轴本身拐两次弯，折线会拧回父框（实测两条连线折回父框内）。删掉后 `vertical` 只剩两条真规则
     （垂直时间线按层分向、上下生长的树/组织结构图竖着进出），S 型与水平时间线一样整族走曲线。
     **口径说明**：这条是"撤掉没有证据的补丁"，不是"照着亿图截图改线型"——S 型时间线的真实线型
     仍缺实机图样，与 §1.1 的既有口径一致（拿到图样只改分发，不动盒型几何）。
   - **测试口径修正（比上面四条更要紧）**：§1.3-6 补的那两条断言是按**版式码整族**判的，
     而"数斜段"在三次贝塞尔上恒真（控制点本来就横平竖直地摆），曲线族拿到的是假绿灯。

     轴的几何（一条直线段 + 两条短线、起点在中心主题前缘、终点越过最后一个一级分支）、
     以及导出同源（SVG 里比无轴版式多出的两条 `stroke-width="2"` 就是轴身与箭头，
     且轴身 path 与布局输出的字符串逐字相同）。layout.test.ts 240 → 279 例，全库 1293 → 1332 例。
   - 装机复验（第四轮）：**17 个版式全过** —— 10 码整族折线、2 码混用（折线 4 + 曲线 2）、
     5 码整族曲线，其中 6 码断言"轴两条线"、其余断言"没有轴"。逐码截图 `C:/zmind-tgt/elbow-*.png`。
   - 遗留：轴长只保证越过**一级分支**的远侧缘，深层子树比它更靠前时轴不跟着加长
     （亿图的实际规则缺截图级证据）；超出量 16、箭头 9x5 同样按常识取。
   - 顺带记一笔：`DocProperties.timelineWidth`（.emmx 的 `TimelineWidth`，我们**读也写**、默认 1000）
     在布局里没人用 —— S 形时间线的折返列宽是 `layoutWinding` 里写死的 420。
     单位口径没证据（1000 直接当 px 会把分支摊得过开），所以先记账不动手；要接就得先拿到实机图样。

9. **新补（已落地）：交叉树两码 + 扇形放射图**。26 → 29 码，`LAYOUT_LABELS` 加码即自动进全码回归。
   - **交叉树（`stagger` / `staggerUp`）**：这一族的名字说的是**线**，不是框。新函数 `layoutStagger`
     按层分行，但每层不按"父节点居中于自己子树"排，而是先排完各家第 1 子、再排各家第 2 子，
     父与子因此必然错位；连线由新画法 `slantPath` 出**一条线段**（父框近侧边中点 → 子框近侧边中点），
     错位让相邻分支的线段真的相交。盒子仍严格互不压（同层按宽度贪心铺、层间按行高分隔）。
     与树状图（向下对称）的区别有断言兜着：同层左右顺序必须不同。
   - **扇形放射图（`sunburst`）**：第一版是给 `layoutRadial` 开角区间参数、取上半圈（`-π..0`，
     y 轴向下即根的上方），**装机目检不合格**：放射图的半径是"从各自父节点量"的链式偏移，
     链到第三四层就整张图斜着甩出去，看着是一坨串不是一柄扇（截图 `C:/zmind-tgt/elbow-扇形放射图.png` 首版）。
     改成独立函数 `layoutSunburst`：**以中心主题为圆心的同心环** + 上半圈，扇区仍按子树叶子数加权分，
     所以同一层的主题踩在同一道弧上 —— 这才是"扇形"。测试跟着加一条"二级分支也同处一圈"，
     链式画法一旦回来就当场红（一级分支同圈那条抓不到，两层都还是同圈）。
     `layoutRadial` 本身**没动**：放射图该不该也改成同心环，缺参考软件的实机图样，不顺手改。
   - 测试口径跟着改：斜线族"没有 C"，原先的折线检测（筛 `!d.includes("C")` 再数斜段）会把它判挂，
     所以先按码摘出去（`isSlantFamily`），再断言"每条连线恰好两点 + 交叉对数 ≥ 1"。
     新增交叉判定用的是严格相交（同父兄弟共端点不算交叉）。layout.test.ts 279 → 313 例，
     全库 1332 → 1366 例。
   - 证据边界：`qm-cn.tsv` 只给了名字（`MainWindow / Stagger = 交叉树`、`Stagger Up = 交叉树向上`、
     `Sunburst Chart = 扇形放射图`），**没有**给几何。上半圈的朝向、错位排布的具体次序、
     扇形要不要留根那一侧，都是按名字和蓝本"树形交叉线（非直角连线）"这句推的；
     拿到实机图样之前不扩张成规则（例如"半圈"改成任意角度、"错位"改成别的遍历序）。
   - 键盘方向：`stagger` / `staggerUp` 进画布的 `VERTICAL_LAYOUTS`（沿 y 生长，"下钻"键往下去）；
     `sunburst` 与放射图一样按 `side` 走横向键向。
