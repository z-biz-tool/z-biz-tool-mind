4. **新发现（已修）：垂直时间线把一级分支摞回同一行**。`layoutSpine` 无论横竖主轴，
   交替/斜刺的偏移都写在 y 上，竖直主轴时正好抹掉了沿轴推进的 y。
   实测：分支A × 分支C 重叠 53x32。改为「推进坐标走主轴、交替偏移走垂直轴」，
   并把竖直主轴的子树展开函数从 `layoutVerticalTreeSubtree` 换成横向展开那一个
   （换完前者的唯一调用点消失，已删，连带删掉只它用的 `vGap`）。
   连线随之按层分向：一级分支竖着接、再往外的子分支横着接。
5. **新发现（已修）：组织结构图（上下双向）把分支压进中心主题**。`assignSubtreeY`
   在 depth=0 时只让开自身半高，等于从根的圆心起算。实测：中心主题 × 分支A 重叠 25x18、
   × 分支B 重叠 56x18。改为先让开「根半高 + 间距」。
6. **新发现（已修）：直角折线族里混着斜线段**。这条只能靠**装机目检**发现——坐标断言全过，
   因为盒子位置本来就对，错的是画线。真机截图上 树状图（向下对称）/组织结构图（上下双向）
   的分支线中间是一段斜线，与 `buildConnectors` 上方「树/组织结构图用直角折线」的注释不符；
   上行枝的连线还从中心主题**底边**出发，先穿回父框再折上去。
   根因：`elbowPath` 非竖直分支写的是「横 → 斜 → 竖」三段（`.replace` 拼出来的那条斜段），
   竖直分支写死「底出顶进」。处置：两个分支都改成纯轴对齐折线，进出边跟随子节点方向
   （`Math.sign(c.y - p.y)` / `Math.sign(c.x - p.x)`）；`treeDownSym`/`treeUpSym`/`orgUp`/`orgDown`/`orgBoth`
   归入竖直折线，`matrix` 走横向 Z。垂直时间线的二级分支顺带修好落点（原来进子框顶边，现在进近侧缘）。

   必须落在父子框的相对边上。layout.test.ts 175 → 189 例，全库 1205 → 1219 例。
   （这两条的**判定口径**随后被 §1.3-7 修过：按版式码整族判斜段，在曲线上是恒真的假绿灯。）

7. **新发现（已修）：主轴版式（时间轴/鱼骨）四处几何真错**。来源是 §1.3-6 修完之后**重装再目检一遍**——
   上一批只对了折线的画法，没验主轴的推进量，目检第二轮才露出来。
   - ① `layoutSpine` 的推进坐标从**根圆心**（`cursor = 0`）起算，首枝的近侧缘因此落在根框之内
     （装机实测：垂直时间线 根底边 17.5、首枝顶边 15）。直角折线于是"从底边出来又折回根框里"。
     改为从根的外缘（`root.w/2` / `root.h/2`）起算。
   - ② `layoutHorizontalTreeSubtree` 里写的是 `setX(c, c)`，而 `setX` 第一行就是
     `n.x = parent.x + side * hGap(parent, n)` —— 自己当自己的父节点，每个子节点被平白多推一格
     （自身宽 + 间距），整棵子树压到下一个主分支身上。改为 `setX(c, node)`，并去掉已经走不到的
     `parent === null` 分支。
   - ③ 水平主轴把 `side`（上下交替的符号）当成子树的左右符号用，子枝甩回根框那一侧
     （实测 水平时间线 的 A一/A二 落在 x=-30，压住根框 31x16；鱼骨图（右）同一条）。
     改为：竖直主轴用 `k.side`（外侧=左右，正好同号），水平主轴沿主轴向前用 `opts.dir`。
   - ④ 沿主轴的步长用了 `estimateWidth`，那是"兄弟并排"的量法，用在横着长出去的子树上短一截
     （实测 水平时间线 的 A一一 右缘 296.5 撞进 分支C 左缘 293，压框 4x30）。
     新增 `forwardReach`：自身中心 → 子树最外缘，步长改为 `k.w/2 + forwardReach(k) + spacing`。
   - ⑤ 顺带清掉一条我自己上一批加的补丁：`buildConnectors` 里
     `code.startsWith("timeline") && code !== "timelineHorizontal"` 把 S 型时间线整族强推成直角折线，
     而它主轴本身拐两次弯，折线会拧回父框（实测两条连线折回父框内）。删掉后 `vertical` 只剩两条真规则
     （垂直时间线按层分向、上下生长的树/组织结构图竖着进出），S 型与水平时间线一样整族走曲线。
     **口径说明**：这条是"撤掉没有证据的补丁"，不是"照着亿图截图改线型"——S 型时间线的真实线型
     仍缺实机图样，与 §1.1 的既有口径一致（拿到图样只改分发，不动盒型几何）。
   - **测试口径修正（比上面四条更要紧）**：§1.3-6 补的那两条断言是按**版式码整族**判的，

      后代误算进来，第一版据此把"枝内后代全跟上"读成了假红；② 盒子位移必须按数组下标取
      （`pos()` 给的是 `[x,y]`，写成 `p.x` 得出一串 NaN，`Math.abs(NaN)<=2` 为 false，
      于是"动了 8 个盒子"这种话毫无意义 —— 判据要先自检：位移集合非空且等于期望下标）。
    - 拖动过程中**整枝实时跟随**（同一条 §1.3-12，2026-10-09 补上，替掉原来的单框虚线预览）：
      `LayoutInput.liveBranch` / `RenderOptions.liveBranch` 是"只进这一帧"的临时位移，
      走的仍是 `applyBranchOffsets` 那一步（叠在已存 `Shape.offset` 之上），所以连线、主轴、外框
      在拖动中就跟着整枝重画；model 一个字都不写，撤销栈在松手时才涨一条。
      画布侧因此不再需要 `ownBox` 当基准：位移直接按指针算（`w - start`，取整），
      预览与提交用的是同一个整数增量 —— 松手不跳位是断言出来的，不是"看起来差不多"。
      这条链路必须有一处**转发断言**：`paintPage` 收下 `liveBranch` 却不转给 `computeLayout`，
      引擎层的断言照样全绿（它们直接调 `computeLayout`），画布却是死的 —— 所以
      layout.test.ts 里额外比了 `paintPage(page,{liveBranch})` 与 `paintPage(page)` 的逐盒差值；
      把那一行转发删掉，这条当场红（实际 [[0,0],[0,0],[0,0]]）。
    - **第一版装机复验被打回，判据是"每一步都快照"**。原实现写的是"命中别的主题就让位给挂树提示、
      同时清空实时位移"，听起来合理（那一次是改父不是搬枝），真机上却是：拖过邻居那一格，
      整枝**弹回原位**，下一步又跟上来 —— 手在动、框不动。第一版只在第 2、6 步取证，
      于是读到 `第 2/6 步 动了 []`，差点当成"快照时机"糊过去。改成每步都快照 + 读屏幕上的预览矩形才看清：
      `step 2/3` 各多出一个 `stroke-width=2 fill=none` 的实线矩形（那就是挂树预览），
      `step 1/4/5/6` 没有 —— 因果对上了。现在的判据是**只要还在拖就一直在跟**，
      挂树预览照旧画在宿主框上，两者不再互斥（`dragTopic` 的 move 分支去掉了 `setLiveBranch(null)` 那条回头路）。
      装机复验（同一台机器、同一个脚本、覆盖安装后）：6 步全部 `动了 [1,2,3,4]` 且位移与当步期望逐值相同，
      第 2 步那个挂树预览矩形**还在**（跟着走和给提示不再互斥），松手不跳位、撤销栈 8/8 → 9/9、
      Ctrl+Z 之后 8 个盒子一格都不差。这条"每步都快照"的判据要留着：只抽两步看，这类闪退看不出来。
      测试计数：layout.test.ts 389 → **402 例**，全库 1466 → **1479 例 / 0 挂**。
    - 证据边界：蓝本只给了名字，没有参数面板截图 —— 亿图到底是存 per-branch 偏移，
      还是干脆把那一枝转成浮动主题，本地没有实机图样。选型（只到二级、叠加式偏移、可复位）
      按名字与 P-2 契约推得，改了要留痕。
