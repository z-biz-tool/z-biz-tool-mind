## A-01 [P0·正确性] 快捷键标签测试平台耦合，macOS 本机必挂 2 例

**现象**（`npm test` 实测）：21 文件 980 例，978 过 2 挂，全在 `tests/shortcut.test.ts`：

```
✗ 标签跟着改 — 实际 "⌘⌥F" ≠ 期望 "Ctrl+Alt+F"        （tests/shortcut.test.ts:61）
✗ Ctrl+Shift+S 的写法 — 实际 "⇧⌘S" ≠ 期望 "Ctrl+Shift+S"（tests/shortcut.test.ts:104）
```

**证据链**（逐环实测）：
1. `src/utils/shortcuts.ts:329` `shortcutLabel(cmd, mac = isMac())`、`:311` `chordLabel(chord, mac = isMac())`——
   缺省参数取运行环境判断。
2. `src/utils/shortcuts.ts:303` `isMac()`：无 navigator 的环境按 Windows 布局；
   **但 Node 21+ 自带全局 `navigator`**，本机 node v22.22.3 实测 `navigator.platform === "MacIntel"`，
   命中 `/mac|iphone|ipad/i` → mac 布局。
3. `tests/shortcut.test.ts:103` 的注释「node 里没有 mac 的 platform，这里只断言非 mac 那一路」
   ——写测试时的前提在 Node 21+ 已经不成立；断言却没显式传 `mac=false`，于是"想测哪一路"漂移成"node 在哪就测哪一路"。

**CI 为什么没拦**（desktop-build.yml 实测）：
- ubuntu job 跑 `npm test`：runner 的 `navigator.platform` 非 mac → isMac()=false → 两例按 Windows 布局断言 → 绿；
- `runs-on: macos-latest` job（yml :95）只跑 `cargo test` + `build-desktop`，**不跑前端测试**。

净效果：**CI 全绿、mac 开发机红**——恰恰漏掉了 mac 这一路的回归。

**影响**：mac 上任何人对 shortcuts 相关代码跑本地测试都会先吃 2 红，污染"红=我改坏了"的信号；且 mac 布局本身零测试覆盖。

**修复方向**（按测试作者本意最小修）：`:61` 改 `shortcutLabel("search", false)`、`:104` 改 `chordLabel("ctrl+shift+s", false)`，
同时把 `:103` 注释改为"显式传 false 锁非 mac 布局（Node 21+ 有全局 navigator，不传会跟宿主平台走）"。
可选加固：再补两行 `mac=true` 断言（`⌘⌥F` / `⇧⌘S`），让两路布局都有锁。→ T-0-1

## A-12 [P0·互操作 · 已办（批 3G）] 任何一次最小编辑都会把整颗 Shape 重建，顺手洗掉亿图的连线引用与路径缓存

**证据**（2026-10-10，批 3F 装机复验时顺手抓的；取证手法见 03 §1.3-21 末条的"标签/属性点名器"）：
装机版打开亿图自己写的 `系统测试.emmx`（206 主题、432 Shape），只点一次「展开全部（22）」再 `Ctrl+S` 原地存盘，
差分两份 `page/page.xml` 的标签与属性计数，得到（预期只有 `Toggler 22 → 0`）：

| 掉的东西 | 条数 | 归属 |
| --- | --- | --- |
| `ToSuper` | −22 | `<LevelData>` 里，指该主题连向父亲的那条 MMConnector 的 id |
| `Geometry` / `MoveTo` | −44 / −44 | `<Geometries>` 的路径缓存（`buildShape` 写死 `<Geometries/>` 空） |
| `LineTo` | −110 | 同上 |
| `X` / `Y` | 各 −154 | 同上 |
| `Paragraph` | −22 | 亿图写两个 `<Paragraph>`（`IX=0` 带 `SpLine`、`IX=1` 带 `IndFirst`），我们只回写一个 |
| `ShapeFormat@QuickMask` | −22 | 原文件每个 ShapeFormat 都带 `QuickMask="4095"`，重建后没有 |
| `CX@B` / `CX@P` | −44 | `<Transform><CX B="1" P="0" V=…>` 的绑定属性，重建后只剩 `V` |

同一批差分还显示**凭空多出来**的 `Rounding`(+22) / `LineCap`(+22) / `LineFormat@LineStyle`(+22) / `Character@Style`(+23) —— 那是 `buildShape` 的默认值，不是文件里原本有的。

**根因**：`codec.ts::rebuildShape` 的判定是"整颗 Shape 的 sig 变没变"（`sigOfShape` 含 `JSON.stringify(s.extras)`），
变了就整棵交给 `buildShape(shape, ctx, raw)` 重建；而 `buildShape` 只建模它认识的那几类子元素，
`LevelData` / `Geometries` / `Transform` / `ShapeFormat` / `Text` 全都在 `SHAPE_OWN_TAGS` 白名单**里面**，
所以 `carryUntouched` 一条也带不回来。**改一个字的编辑 = 重写整颗形状。**

**影响**：与折叠无关，是**所有编辑**的公共路径 —— 改标题、改颜色、拖动、折叠，任何一次存盘都在削这些码。
用户侧的表现是"在复刻里存过一次，亿图再打开时连线/形状外观/段落缩进不对了"，
而我们的往返测试**全绿**（`modelEquals` 只比模型，模型里本来就没有 ToSuper 与 Geometry），没有任何信号。

**修复方向**（→ 批 3G）：把回写粒度从"整颗 Shape"降到"变了的子树" ——
对每个自有子节点单独算 sig，未变的子节点直接复用 `raw` 的那一份（`ToSuper`、`Geometries`、`QuickMask`、`CX@B` 就都活了），
只有真的建模过且改了的子节点才重建；`buildShape` 发明默认值的那几处要按"源里没有就不写"收口。
验收口径必须换成这台点名器：**真亿图文件 → 改一处 → 存盘 → 标签/属性差分只允许出现预期的那几条**。

**【已办 · 批 3G · 2026-10-10】** 回写粒度降到"一颗子节点一次裁决"：`buildShape` 里每个自有子节点走
`keep(tag, same, built)` —— `same` 成立就把**原节点对象**直接挂回盘上（一字节不经过我们的想象），不成立才按模型重建；
重建时也按"源里有就跟着走，源里没有就不发明"收口（`adoptAttrs` 带回未建模属性、`buildLine` 的
`had(tag)`、`ShapeStyle` 与 `<Layout>` 邻居原样带回）。`same` 的口径按子树语义分别定，不是一刀切：
`Transform` 比 round 后的四个数（亿图写 707.621、我们写 707.62，那是量具精度不是用户改过）、
`ShapeFormat` 比"把原文读一遍再与模型比"（亿图 `<FillFormat/>` 与我们的 `<FillFormat Type="None"/>` 字不同义同）、
`Text` 比 `parseRichText` 的 canon、`LevelData` 逐字比父子指针。

改完的实测（三份真亿图文件 × 七种最小编辑，`C:/zmind-tgt/wdprobe2.mjs`，口径就是上面要求的那台点名器）：

| 最小编辑 | 系统测试 | 软件质量 | 测试基础 | 剩下的那几条是什么 |
| --- | --- | --- | --- | --- |
| 改一个主题的标题 | **0** | **0** | **0** | 什么都没有（原来满屏的削码就是它触发的） |
| 折一支 / 展开全部 | 2 | 2 / 2 | 2 | 只有 `Toggler` 与 `Toggler@V` |
| 改一个主题的填充色 | 17 | 12 | 12 | 被点那颗自己的路径缓存失效（−`Geometry`/−`MoveTo`/−`LineTo`/−`X`·`Y`）+ 真多出来的 `Color`、`FillFormat@Type` |
| 拖动一个主题 | 14 | 12 | 12 | 同上：位置变了，缓存按理应作废 |
| 新增一个子主题 | 42 | 42 | 42 | 全部是这一颗自己的足迹，别的一颗不动 |
| 删掉一个叶子主题 | 93 | 80 | 80 | 全部是那一颗的足迹（每条 −1/−2）+ 父亲的 `LevelData` 少一号 |

表里没有**增加**的意外键：新增/删除那两行的每一条差分都能落到"这一颗形状本身"，`Shape` 计数 +1 / −1 各一次。

这一批在写侧顺手抓到、也一并办掉的三条（都是新测试逼出来的，不是我推演出来的）：
① **值级损失**（键级点名器天生看不见，所以 A 层夹具钉的是值）：`TextBlock@TextFormatMask` 被我们的常数 `10224`
洗掉了亿图写的 `0`、`Character@BkColor` 整条丢、第二条 `<Paragraph IX>` 上的 `SpaceBefore/SpaceAfter` 整条丢 →
`adoptAttrs(built, raw, modeled)` 把原节点上我们没建模的键带回来，但 **`modeled` 名单里的键一律不带**：
否则用户在界面里刚取消的加粗，会被原文件的 `Style="1"` 原样复活（夹具 105 专门钉这一条）。
② `coveredBy` 是单向的（只看"模型这一边断言的项在不在原节点里"），删除子主题时它会说"原节点已经包住了"，
把还指向已删主题的那份 `<SubLevel>` 带回盘上 —— 又留悬空引用又没真删掉；`LevelData` 因此改用逐字指针比对。
③ 见 **A-15**。

量具：`tests/writediff.test.ts` 118 例（A 层合成夹具：把 `ToSuper`/路径缓存/第二条段落/`QuickMask`/`BkColor`/
`TextFormatMask="0"`/`ShapeStyle V="5"`/`CX` 的精度位与 B·P 锚/连接线占的号段，一颗一颗亲手种进亿图写法的夹具，
走界面同一套 tree API 改一处，按**值**验它还在；B 层真文件：未编辑过的 `<Shape>` 逐颗比字节 + 逐场景差分白名单与方向断言），
全库 2177 → **2295 例 / 28 文件 / 0 挂**，`tsc` rc=0；变异验证 `C:/zmind-tgt/mut-3g.mjs` 11 条 **11 杀**
（把每一处无损机制逐个打掉，看测试是否真会挂；先跑成 0/11 是我的量具 bug —— `execSync` 在用例挂时抛异常，
我把 stdout 丢了，已修）。

诚实的残留（都写在这里，不藏）：重建 `<Text>` 时内层 `Transform` 的 Width/Height 用我们的估算（亿图的值只在原节点被复用时才留）；
`Paragraph@SpLine="100"` 我们总写；重建 `ShapeFormat` 只合并原属性、不合并我们没建模的子节点；

我们的序列化器把 `>` 写成 `&gt;`（亿图写原文），合法但字节不同，所以字节级比对前要先做实体归一。
